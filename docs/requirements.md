# 需求与产品边界

本文是栖点当前功能和验收规则的基线。原始视觉与交互参考保存在 `private_wiki_prototype.html`；正式产品以当前源码和本文为准。

## 产品定位

栖点是运行在个人设备上的 Docker 私人知识库，面向电脑和手机浏览器。笔记、书签、账号、附件和备份只保存在用户自己的 Docker 持久化目录。

- 笔记与书签是同级主体功能。
- 允许在同一实例创建多个隔离账号，各账号的数据彼此独立。
- 默认使用本地 HTTP 9908，适合可信局域网；公网访问由用户自己的 HTTPS 反向代理负责。
- 数据容量达到限制时必须明确报错，不能静默丢弃内容。

## 账号与权限

- 第一次启动时引导创建管理员，用户名预填 `admin`，密码始终由用户输入，没有默认密码。
- 登录只使用账号名和密码。
- 密码至少 8 个字符，并满足大写字母、小写字母、数字、符号中的任意两类。
- 登录会话连续 3 天未使用后失效，绝对有效期为 7 天；使用 HttpOnly、SameSite=Strict Cookie，并由服务端执行期限校验。
- 所有数据、附件、备份、账号和更新 API 均须鉴权；生产配置缺失时拒绝访问。
- 各账号的知识库、正文历史、头像和附件相互隔离。
- 登录后修改密码须验证当前密码；修改成功后注销其他会话。
- 设备管理员可从容器终端重置密码；重置不影响数据。
- 首个管理员创建后默认关闭注册，只有设备管理员明确开启时才显示注册入口。

## 笔记

- 内置普通笔记、网页摘录、命令速查和故障排查类型；类型可以新增、改名和删除。
- 删除仍被使用的类型前必须选择迁移目标，并始终保留至少一个类型。
- 支持分类、标签、来源网址、重要收藏、最近编辑和全文搜索。
- 新笔记先进入私人草稿；发布后进入个人阅读列表。
- 已发布笔记再次编辑时，阅读版保持不变，直到用户点击“保存笔记”。
- 发布只改变当前账号的阅读状态，不生成公开链接。
- 单篇笔记可导出离线 HTML；完整知识库可导出 ZIP。
- 删除笔记时移入回收站，保留 30 天，可还原；用户确认清空回收站后才永久删除。

## 编辑器与粘贴

- 编辑器使用 Tiptap 3 和 ProseMirror，内部转换使用 Tiptap JSON，持久化继续保存清理后的 HTML。
- 支持标题、粗体、斜体、下划线、删除线、颜色、对齐、列表、引用、链接、分隔线、表格、代码、图片、图注、提示块和折叠内容。
- 表格在手机端允许横向滚动；代码块保留缩进、换行和语言信息并提供复制。
- 支持四种粘贴方式：保留网页格式并自动识别 Markdown、整理纯文本、按 Markdown 解析、仅纯文本。
- 标准 Markdown 应正确处理标题、嵌套列表、GFM 表格、代码围栏、图片、提示块和折叠块。
- 普通文字不能因为自动识别而被错误重排；解析失败时保留原始文字。
- 空白笔记可从首个 Markdown 标题或首个有效文本行自动填充标题。
- HTML 粘贴必须移除脚本、事件属性、表单、iframe 和危险 URL。
- 远程图片不自动抓取；只有用户上传的文件才进入本地附件和完整备份。

## 保存、多设备与历史

- 输入停止约 250 毫秒后进入串行保存流程。
- 界面只有在 Docker 服务端 SQLite 事务完成后才能认为保存成功；进入队列不等于已保存。
- 正常输入、编辑、保存和发布过程不显示常驻状态提示。
- 生产环境不把正文作为长期副本保存在浏览器中。
- 前台每 2.5 秒检查一次服务端版本号，页面重新进入前台时立即检查。
- 不同笔记、不同字段和不重叠正文修改可以自动合并；重叠冲突不得自动覆盖。
- 冲突时保留当前页面内容和 Docker 服务端版本，并提供对照备份与明确恢复操作。
- 网络中断期间保留当前页面修改，连接恢复后重试。
- 正文历史每分钟最多生成一个检查点，按时间保留最近 20 个；正文历史不代替完整备份。

## 书签

- 只保存标题、网址、收藏状态和原始分组，不抓取网页正文；界面可按网址加载站点图标，失败时使用文字图标回退。
- 支持 Chrome、Edge 等浏览器导出的 Netscape HTML，保留多层目录、空分组和顺序。
- 导入前显示新增、重复、忽略和分组预览；确认后直接追加合并，不强制生成备份。
- 同路径同名分组合并，同一分组内相同网址去重，不删除查询参数。
- `javascript:`、`file:` 和包含账号密码的 URL 必须拒绝。
- 支持搜索、新建分组、改名、移动、排序、收藏、单项删除、批量移动和清空书签。
- 删除书签或分组时移入回收站，保留 30 天，可还原到原分组与顺序；清空全部书签也可在回收站中逐项还原。
- 永久清空回收站前须弹出明确确认，用户可以取消；确认后不可撤销，不强制下载备份。
- 支持浏览器兼容 HTML 导出；书签与回收站同时进入整库快照和完整 ZIP。
- 首页分组可独立展开和收起，也可全部展开、全部收起并在区域内滚动；可选择单列或双列排列。
- 主题、编辑器粘贴方式、侧栏笔记类型展开状态、首页书签排列与分组展开状态、书签页目录与树形分组展开状态均保存到当前账号的 Docker 数据中，并在该账号登录的设备间同步。
- 当前页面、搜索文字、滚动位置、临时菜单、选择项和整理模式属于当前操作过程，不作为账号偏好保存。
- 目录最大 32 层，书签与分组总数最多 10,000。

## 文件、备份与限制

| 项目 | 当前限制 |
|---|---:|
| 单个附件 | 8 MiB |
| 每账号附件总量 | 100 MiB |
| 每账号知识库正文 | 1 MiB |
| 正文历史 | 最近 20 个检查点 |
| 回收站保留时间 | 30 天 |
| 浏览器书签导入文件 | 5 MiB |

完整 ZIP 包含笔记、类型、分类、标签、书签、回收站和原始附件。结构迁移、完整导入和可能覆盖数据的操作前必须保留备份。设备硬盘、Docker 卷或数据目录损坏仍会造成数据丢失，用户应另外备份挂载目录。

## 部署与更新

- 正式镜像发布到 `docker.io/luckyalanzhou/qidian`，同时提供 `linux/amd64` 与 `linux/arm64`。
- iStoreOS 24.10 / 25.12 均可用 `.run` 自解压安装 LuCI、Compose 和宿主管理脚本；该安装方式不依赖 opkg 或 apk，不在设备上编译前端。
- OpenWrt 与 iStoreOS 24.10（opkg）发布架构无关 `.ipk`；25.12（apk）发布架构无关 `.apk`。
- 所有 LuCI 部署都必须实时读取当前设备 Docker Root Dir，再创建 `volumes/qidian/data`，不得写死任何设备路径。
- 通用 Docker 使用当前 Docker Root Dir 管理的 `qidian-data` 命名卷。
- Web 只从固定 GitHub Release API读取版本信息，不上传知识库数据。
- 只有首个账号可发起设备更新；更新请求通过受限目录交给宿主代理，容器不得挂载 Docker Socket。
- 更新代理按本机安装来源下载带版本号的 `.run`、`.ipk` 或 `.apk` 和 SHA-256，校验后才执行。
- 更新管理文件后等待 10 秒再拉取镜像和重建服务；新版本服务可用后，网页等待 5 秒并自动刷新。
- 更新失败必须保留实时日志和重试入口，数据目录不得改变。

## 界面要求

- 使用简体中文，提供跟随系统、浅色和深色三种主题设置。
- 桌面端保留侧栏和顶部搜索；手机端使用底部导航和适合触控的面板，并适配 iOS Safari 安全区。
- 手机端的笔记操作菜单应定位在所点击的操作按钮附近，保持操作对象和菜单的视觉关联。
- 笔记与书签在首页以同等权重展示，不用大面积装饰区压缩内容空间。
- 顶栏显示当前版本，有新版时显示红点；版本详情在手机端使用居中面板。
- 安装和更新日志在 Web 与 LuCI 中实时刷新，手机端不得因日志框过大而缩小整个页面。
- `Ctrl/Command + K` 打开全局搜索，`Ctrl/Command + S` 提交当前编辑，`Esc` 关闭浮层。

## 非目标

当前不提供协作编辑、AI 问答、向量检索、OCR、提醒、附件内容索引、自动异地备份或端到端加密。

## 验收原则

- 数据兼容和不丢失优先于界面更新。
- SQLite、DOM、构建与安装包测试通过后，仍须分别进行桌面浏览器、手机实机和目标 OpenWrt / iStoreOS 设备验收。
- 源码、Git、CI、Docker Hub 和设备运行状态必须分开报告，不能用构建成功代替设备验证。
